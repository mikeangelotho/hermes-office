# Local ambient office — implementation and acceptance plan

**Goal:** leave the Office running on a Windows desktop as a quiet, real view of this machine’s Hermes activity. Keep the existing signal figures, glass architecture, campus identity, and interactive standalone interface. No laptop connection, public live iframe, startup-task installation, OS wallpaper modification, or gateway changes in this pass.

## Art direction

Primary visual reference: Marek Brzezinski, *Visual development of Braindance (in-game screenshots) – Cyberpunk 2077*, https://marekbrzezinski.artstation.com/projects/nYBAGE. The director reviewed six actual gameplay stills, not just the captions. Look at the grounded furniture and footprints, dark and broken outer volumes, brighter resolved edges and localized amber practicals in the visual layer; not the timeline, typography, characters or thermal full-screen treatment. Create original geometry and materials only. No source images, game assets, logos, flashing, screen-wide glitches, downloaded fonts or runtime network calls. The reference contact sheet is development-only and is not part of the app.

## Parallel ownership and contract

1. **Observation (worker):** own `bridge/**`, validation portion ONLY of `server/office-api.ts` (through `validateSnapshot` and related constants), `src/domain/types.ts`, `src/domain/snapshot.ts`, related new collector/contract tests. Keep existing `snapshot.agents` profile rows, `activeSessions` and demo backwards compatible. Add optional top-level `participants?: OfficeParticipant[]`. Each participant is an OfficeAgent-compatible row plus `kind: 'session'|'subagent'`, `profileId: string`, `parentId?: string` when an observed parent is present. `id` and `parentId` are stable, opaque local render keys, never native IDs. Neutral names (e.g. ‘Session A…’, ‘Subagent B…’); generic fixed role/activity, no private names or task text. Only verified in-flight evidence; ‘subagent’ must be backed by explicit runtime evidence such as `source == 'subagent'`, not every fork/compression. Treat missing metadata as unknown, keep limits enforced, dedupe leases/workers, avoid exposing or reading transcripts, prompts, outputs or secrets. Tests include visible parent and children, ended/expired excluded, identical evidence deduped, relationship and privacy validation. Parent owns interpreter resolution and the plugin's process launch section (~146 onwards), so do not change them.
2. **Environment (worker):** own `src/scene/**` except shared type files outside the scene, own new environment tests. Add an original physically continuous floor with contact/support and visible rear/side service architecture (floor slabs, wall bays, structure, practical lighting, edge fragments as appropriate). The room silhouettes and agents remain brightest. Front(camera) sightlines open, landmarks visible in overview and room focus. Deterministic, static/batched low-cost geometry; no flashing, raster overlays, third-party assets, blank blue field or aggressive permanent camera drift. Respect existing budgets, pause/reduced motion, resizing, glass, picking, annexes and disposal. Render a real screenshot; judge value separation in pixels at the original camera.
3. **Viewer (worker):** own `src/Experience.tsx`, `src/domain/presentation.ts`, new `src/domain/…` display helper(s) EXCEPT type/snapshot/state files, `src/lib/status.ts`, CSS, controls/components as needed except scene engine, and dedicated viewer tests. Top-level `/?view=ambient` is a local **live** leave-on display; simple discoverable entry/exit in standard view; quiet chrome, accessible way back, existing fullscreen available where supported, no forced camera or motion. Include subtle live/unknown indicator. A real embedded ambient request must stay demo-only/no requests, as must existing `?embed=1`, `?view=embedded`, `?view=hero` (public safety overrides live). For live scenes/roster, replace a profile's avatar with its active participants when known, never double-count aggregate profile + its people. Show child/parent relationship with safe labels in the inspector. With no valid observation say ‘Activity unknown’ instead of ‘0 working’; keep stale/partial honest. Never borrow demo figures in a failed live view. An explicit non-ambient demo still works. Add tests for display decisions and public/ambient routing; do not depend on availability of new declarations while writing tests.
4. **Launcher, integration and acceptance (lead):** own launcher, package scripts, interpreter discovery, project docs and integration harness; do not touch gateway software or other services. Resolve desktop Hermes Python without the Microsoft Store alias, without hard-coded version, and bind to `127.0.0.1:3002`. Reusable command or double-click launcher, healthy reuse/clear errors, no auto-install/self-discovery over the network. Preserve unrelated `bun.lock` and working tree. Verify assembled source/build/tests and local real browser, and verify actual listener owner before replacing only Office. Independent review before handoff.

## User-visible acceptance

- A live top-level ambient tab shows a resolved grounded scene on a fresh launch; interaction and normal/fullscreen views still work. Taking the feed away shows unknown without switching to fabricated data. Public embed makes zero `/api/office` requests.
- One real local parent with two verified children renders as **three** distinct workers, not a fourth aggregate profile; finishing a child removes just that child at the next observation. If no live children remain at rollout, distinguish deterministic fixture from genuine observation and use a bounded real delegated verification if needed. Independent working sessions remain distinct. No raw runtime IDs, prompts or task titles in the browser snapshot.
- Verify screenshots of live ambient, an interactive room, and/or same-camera pre/post art at desktop size; make sure the floor actually meets the rooms and the perimeter does not obscure subjects. Keep software-renderer figures separate from physical GPU/battery claims.
- Verify API success through the durable loopback launcher, bounded render budgets, pause/hidden-tab behavior where available, and no regressions in the public-safe embed or the current test suites. Leave a working local URL and a relaunch path. Development-only screenshots/evidence stay outside the project.
